# Шаблоны описаний задач

Ссылки на статьи — по ID (`{{kb.architecture.overview}}`), на задачи — по ID (`{{project}}-34`). Описание должно быть самодостаточным: исполнитель не видит переписку, только YouTrack и репозиторий.

## [EPIC]

```markdown
## Ценность
Кто получает, что именно, почему сейчас. 1–3 предложения.

## Источник
Идея: {{project}}-1.

## Границы
**Входит:** ...
**Не входит:** ...

## Критерии успеха
- Измеримые / проверяемые утверждения.

## Аналитика и архитектура
- Сводка влияния: см. комментарий `[AGENT:DECISION]` system-analyst.
- Статьи: {{project}}-A-… (функциональные требования), {{project}}-A-… (модель данных), ADR: {{project}}-A-…
- Проект эпика: {{project}}-A-… (архитектура эпика)

## Порядок реализации
1. STORY {{project}}-.. → 2. STORY {{project}}-.. (параллельно с ..)

## Ветка
`epic/<ID>-<slug>` (создаётся автоматически `scripts/agent-loop.sh`)
```

## [STORY]

```markdown
## Сценарий
Как <роль>, я хочу <действие>, чтобы <ценность>.

## Критерии приёмки
1. **Given** ... **When** ... **Then** ...
2. **Given** ... **When** ... **Then** ...
(негативные сценарии и права доступа — отдельными критериями)

## Контекст
Статьи: {{project}}-A-…; ADR: {{project}}-A-…

## Задачи
Создаются как подзадачи, порядок — через `depends on`.
```

## [TASK]

```markdown
## Контекст
Зачем эта задача в рамках STORY {{project}}-.. (1–2 предложения). Статьи: {{project}}-A-….

## Что сделать
Одно атомарное изменение. Конкретно: классы, маршруты, компоненты, миграции, имена.

## Критерии приёмки
- [ ] Проверяемый результат 1 (желательно в виде теста: «feature-тест X проверяет Y»).
- [ ] Тесты добавлены, `scripts/run-tests.sh` проходит (и требования проекта к покрытию, если они есть).

## Затрагиваемые области кода (оценка)
- `app/Actions/...` (новый)
- `database/migrations/...` (новая миграция — конфликтует с другими миграциями этой волны)
- `resources/...` (представления или фронтенд)

## Вне рамок
Что НЕ делать в этой задаче (чтобы исполнитель не расползался).
```

## [IDEA]

Заводит человек, свободной формой. Достаточно: что хочется, для кого, почему. Метка `idea`, `Type: Idea`, `State: Backlog` (`Stage: Backlog` — по умолчанию).
