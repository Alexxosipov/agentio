# Project manager

Опирается на [youtrack-workflow](../youtrack-workflow/SKILL.md): иерархия, статусы, захват, шаблоны. Не дублируй их — следуй им. Шаблоны описаний: [issue-templates.md](../youtrack-workflow/issue-templates.md).

## Вход

- ID идеи в `{{project}}` (`tag: idea`, `State: Backlog`), **или**
- текст от человека — тогда сначала создай идею: `create_issue(project="{{project}}", summary="[IDEA] …", description=<текст>, customFields={"Type": "Idea", "State": "Backlog", "Stage": "Backlog"})`, метка `idea`.

## Процедура планирования

### 1. Захват и контекст
1. `php scripts/yt.php claim <IDEA> --as=pm --plan="Планирование идеи"`. При `LOST` — остановись.
2. `php scripts/yt.php set-state <IDEA> Analysis` (claim ставит In Progress; для идеи фаза называется Analysis). Статусы всегда меняй через `set-state` / `release` — они синхронизируют поле Stage (см. youtrack-workflow, раздел 3).
3. `php scripts/yt.php context <IDEA>`. Прочитай статьи «Обзор продукта», «Глоссарий», раздел «Системная аналитика» и связанные эпики (`search_articles`, `search_issues "project: {{project}} Type: Epic"`), чтобы не дублировать существующее.

### 2. Требования
Сформулируй и запиши в описание идеи (раздел `## Требования`, через `update_issue`, не затирая исходный текст):
- **Цель** — какую проблему решаем.
- **Пользователи** — роли.
- **Границы** — что делаем и что явно НЕ делаем.
- **Критерии успеха** — проверяемые.

**Нехватка данных.** Если без ответа человека нельзя определить существенное (бизнес-правило, роль, объём, внешнюю систему, юридические ограничения), не додумывай. Напиши `[AGENT:BLOCKED]` с конкретными вопросами и вариантами ответов, затем `release <IDEA> --state=Blocked` и остановись. Мелкие технические детали — это допущения, их фиксирует `[AGENT:DECISION]`.

### 3. Аналитика и архитектура — до декомпозиции на TASK
1. Примени скилл **system-analyst** к идее: статьи по 7 слоям обновлены, сводка влияния записана в идею.
2. Набросай эпики (обычно 1; больше — только если части дают ценность независимо). Создай EPIC: `create_issue(project="{{project}}", summary="[EPIC] …", customFields={"Type": "Epic", "State": "Analysis", "Stage": "Backlog"})`, связь `relates to` с идеей, описание по шаблону.
3. Примени скилл **laravel-architect** к каждому эпику: проект эпика, ADR при необходимости, **порядок реализации и параллелизм**. Это вход для шага 5.

### 4. Декомпозиция
Для каждого эпика:
1. STORY — по одному пользовательскому сценарию. Критерии приёмки Given/When/Then, включая негативные и авторизацию. `create_issue(parentIssue=<EPIC>, customFields={"Type": "Story", "State": "Analysis", "Stage": "Backlog"})`. TASK создаются так же: `parentIssue=<STORY>`, `"Type": "Task"`.
2. TASK — атомарные изменения внутри STORY по шаблону (контекст, что сделать, критерии приёмки, ссылки на статьи, оценка затрагиваемых областей, вне рамок). Тест на атомарность: одна цель без «и»; выполнима субагентом без вопросов за один заход; есть проверяемый результат. Тесты пишутся **в той же задаче**, что и код (зелёный полный прогон — условие сборки), отдельные TASK «написать тесты» не создаются.
3. Типовая нарезка для Laravel: миграция и модель → Action (сервис) и Form Request → контроллер и маршрут → джоб или событие → представление, страница или компонент фронтенда (стек проекта — см. `CLAUDE.md` и ADR-001). Каждая — TASK, если по объёму не тривиальна; тривиальные соседние шаги склеивай.

### 5. Зависимости
1. По порядку от архитектора: `link_issues(target=<зависимая>, linkType="depends on", issueToLinkId=<от которой зависит>)`.
2. **Пересечения по файлам.** Для каждой пары задач, у которых пересекаются «затрагиваемые области» (тот же файл, `routes/web.php`, общая миграция или модель, общий компонент), добавь `depends on` в порядке реализации, даже без логической зависимости. Это защита от конфликтов при параллельной работе. Все новые миграции эпика выстраивай в цепочку.
3. Межэпиковые зависимости: на уровне EPIC → EPIC.

### 6. Валидация и Ready
1. `php scripts/yt.php validate <IDEA>` — без проблем (нет циклов, у каждой TASK родитель STORY, у STORY — EPIC, префиксы совпадают с Type, нет пустых STORY).
2. Переводи в `Ready` (`php scripts/yt.php set-state <ID> Ready`) **только полностью описанное**: TASK с заполненными разделами шаблона, STORY с критериями приёмки, EPIC с аналитикой и архитектурой. Порядок: TASK → STORY → EPIC.
3. Повторно `validate`: первая волна готовых задач не пуста (иначе ошибка в зависимостях).
4. `php scripts/yt.php tree <EPIC>` — вставь вывод в `[AGENT:DONE]`.
5. Идея: `[AGENT:DONE]` (эпики, статьи, первая волна задач) → `release <IDEA> --state=Done`.

## Сопровождение

Запускается из `/status`, `/dispatch` или по запросу человека:
- **Пересчёт блокировок:** `php scripts/yt.php blocked`. Ready-задачи, ждущие незакрытых зависимостей, — норма. Задачи, ждущие зависимость в `Blocked`, — эскалируй в `[AGENT:BLOCKED]` у первопричины.
- **Разбор `[AGENT:BLOCKED]`:** если человек ответил комментарием после блокировки — внеси ответ в описание или статью, при необходимости перестрой задачи, верни прежний статус (`php scripts/yt.php set-state <ID> Ready`) и напиши `[AGENT:DECISION]`. Если ответа нет — ничего не делай.
- **Изменение требований:** сначала статья (через system-analyst), потом задачи. Уже сделанные TASK не переписывай — создавай новые.
- **Закрытие** (`php scripts/yt.php set-state <ID> Done`): STORY → `Done`, когда все её TASK в `Done`, STORY прошла review и эпик слит в `{{base_branch}}`. EPIC → `Done`, когда все STORY в `Done` и критерии успеха выполнены. Слияние подтверждай: `git branch --merged {{base_branch}} | grep epic/<ID>`.

## Чек-лист самопроверки

- [ ] Требования: цель, пользователи, границы, критерии успеха записаны в идею.
- [ ] Существенные пробелы не додуманы, а заданы вопросом в `[AGENT:BLOCKED]`.
- [ ] system-analyst и laravel-architect отработали **до** создания TASK.
- [ ] Каждая TASK атомарна, по шаблону, со ссылками на статьи и оценкой затрагиваемых файлов.
- [ ] Задачи с общими файлами или миграциями связаны `depends on`.
- [ ] `validate` без проблем, первая волна не пуста.
- [ ] В Ready — только полностью описанное. Идея закрыта `[AGENT:DONE]` и `release`.
