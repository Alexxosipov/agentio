# System analyst

Опирается на [youtrack-workflow](../youtrack-workflow/SKILL.md). Слои и что в них писать — в [layers.md](layers.md). Шаблон сводки — ниже.

Набор из 7 слоёв — рабочая методика проекта. Её можно заменить, например, на arc42 или BABOK: тогда поменяй `layers.md` и дерево статей.

## Где лежит база знаний

Корневая статья «Системная аналитика» в проекте `{{project}}` и по одной дочерней статье на слой. ID: корень {{kb.analysis}}; слои 1–7 — {{kb.analysis.business}}, {{kb.analysis.users}}, {{kb.analysis.functional}}, {{kb.analysis.data}}, {{kb.analysis.integrations}}, {{kb.analysis.nfr}}, {{kb.analysis.constraints}}; «Обзор продукта» — {{kb.overview}}, «Глоссарий» — {{kb.glossary}} (полная карта — скилл youtrack-workflow, раздел 9). Если ID не подставлены, найди статьи: `search_articles "project: {{project}} Системная аналитика"`, затем `get_article` у корневой статьи (там список дочерних).

Стек проекта — см. `CLAUDE.md` и ADR-001 ({{kb.adr.001}}); аналитика описывает поведение и данные, а не технологии.

## Процедура

1. **Прочитать текущее состояние.** Задача: `php scripts/yt.php context <ID>`. Все 7 статей слоёв целиком (`get_article`; длинные — с `linesOffset`) плюс «Обзор продукта» и «Глоссарий».
2. **Определить затронутые слои.** Для каждого из 7 слоёв: затронут или нет, с одной фразой обоснования. Бизнес-контекст затрагивается всегда, когда появляется новая ценность.
3. **Обновить статьи — без дублей.**
   - Дописывай в существующий раздел, если сущность, роль или правило уже описаны; новый раздел — только для нового.
   - Каждый новый или изменённый блок помечай источником: `({{project}}-12)`, где {{project}}-12 — эпик или идея.
   - `update_article` перезаписывает статью целиком (кроме `append=true`). Поэтому сначала `get_article`, правка в полном тексте, потом запись.
   - Новые термины — в «Глоссарий».
4. **Проверить противоречия.** Сравни новое с уже описанным: правила, права ролей, жизненный цикл сущностей, нефункциональные требования. Найденное противоречие:
   - если решается из контекста — реши и зафиксируй `[AGENT:DECISION]`;
   - если нет — `[AGENT:BLOCKED]` с вариантами (статус задачи → Blocked: `php scripts/yt.php release <ID> --state=Blocked`, планирование останавливается).
5. **Записать сводку влияния** комментарием `[AGENT:DECISION]` в задачу (идею или эпик) по шаблону ниже. Для незатронутых слоёв явно пиши «не затронуто».

## Шаблон сводки влияния

```markdown
[AGENT:DECISION]
**Системная аналитика: сводка влияния (<ID>)**

| # | Слой | Влияние | Статья |
|---|---|---|---|
| 1 | Бизнес-контекст и цели | <что добавлено/изменено> | {{project}}-A-.. |
| 2 | Пользователи, роли и сценарии | ... | {{project}}-A-.. |
| 3 | Функциональные требования и бизнес-правила | ... | {{project}}-A-.. |
| 4 | Данные | ... | {{project}}-A-.. |
| 5 | Интеграции и интерфейсы | не затронуто | — |
| 6 | Нефункциональные требования | ... | {{project}}-A-.. |
| 7 | Ограничения, допущения и риски | ... | {{project}}-A-.. |

**Противоречия:** нет | <описание и как решено>
**Открытые вопросы:** нет | <ссылка на [AGENT:BLOCKED]>
```

## Чек-лист самопроверки

- [ ] Прочитаны все 7 статей слоёв, «Обзор продукта», «Глоссарий».
- [ ] По каждому слою есть вердикт; незатронутые помечены «не затронуто».
- [ ] Статьи обновлены без дублей, новые блоки помечены `(ID)`.
- [ ] Новые термины добавлены в «Глоссарий».
- [ ] Противоречия проверены: решены (`DECISION`) или эскалированы (`BLOCKED`).
- [ ] Сводка влияния записана в задачу и ссылается на статьи по ID.
