## Контекст
Laravel-приложение, разработка ведётся автономными агентами по задачам YouTrack. Нужны явные соглашения, чтобы код разных задач выглядел одинаково.

## Решение
- **Стек и версии:** …
- **Слои:** контроллеры, Form Request, Actions или сервисы, Policy, модели …
- **Структура кода:** стандартные каталоги Laravel по виду класса, внутри них — доменные подкаталоги: `App\<Каталог вида>\<Домен>\<Класс>` (`App\Actions\Listings\PublishListing`, `App\Http\Controllers\Auth\LoginController`, `App\Models\Articles\Article`; домен — модуль «Системной аналитики» или его подобласть; общий для нескольких доменов код — в каталоге вида без подкаталога; на своих местах остаются миграции, сиды, `config`, `routes`, `lang`, каркас, `App\Models\User` и код, который пакеты публикуют по своему пути), если `CLAUDE.md`/`AGENTS.md`, `.ai/guidelines` или `.ai/rules` не задают другую раскладку. Тест зеркалит путь класса (`tests/Feature/Actions/Listings/PublishListingTest.php`), набор `Feature`/`Unit` — по скиллу `testing-best-practices` (код с фреймворком — `Feature`). Перенос существующих классов — только решением человека …
- **Зависимости:** новые пакеты — решение человека; интеграции с сервисами без готового поддерживаемого SDK — через Saloon (`saloonphp/saloon`, скилл `agentio-saloon`) …
- **Интеграции:** есть поддерживаемый SDK — адаптер над SDK, нет — клиент на Saloon; весь код интеграции — в `App\Integrations\<Сервис>` (`app/Integrations/<Сервис>`), тесты — `tests/Feature/Integrations/<Сервис>` …
- **Интерфейс:** Blade / SPA / API — как данные попадают в представление …
- **Очереди:** драйвер, имена очередей, ретраи …
- **Тесты:** фреймворк, требования к покрытию, полный гейт (`composer test`), конкретные тесты (`vendor/bin/pest`) …
- **Качество кода:** форматтер, статический анализ, линтеры фронтенда …
