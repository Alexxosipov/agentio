# Эксплуатация: наблюдаемость, кэш, файлы, безопасность, изменения схемы

Сквозные аспекты, которые проектируются в каждом эпике, а не «потом». Сначала — как это уже устроено в проекте (ADR-001, `config/*`, код); точный API — `search-docs` и `rules/caching.md`, `rules/security.md`, `rules/config.md`, `rules/migrations.md`, `rules/error-handling.md` скилла `laravel-best-practices`.

## Наблюдаемость

- Логи — структурированные, с контекстом: `Log::withContext` / `Context` (переносится в джобы) — ID запроса, пользователя, сущности, ключ идемпотентности. Без паролей, токенов, данных карт и лишних персональных данных.
- Исключения доходят до системы отчётов проекта (`report()`); ожидаемые бизнес-отказы — не ошибки и не шумят.
- Для каждой фоновой и интеграционной операции видно: сколько ждёт, сколько упало, что зависло (команда, запрос, Horizon, панель).
- Алерты — на то, что требует человека: окончательный сбой платежа или сверки, рост `failed_jobs`, длина очереди, открытый предохранитель интеграции.

## Кэш

- У каждого ключа — владелец, TTL и правило сброса (событие модели, явный сброс в Action); имя ключа с версией или тегом, если структура данных меняется.
- Кэш — не источник правды: потеря кэша не теряет данных. Деньги, остатки, права — не из кэша без проверки.
- Дорогие ключи под нагрузкой — защита от одновременного пересчёта (`Cache::flexible`, блокировка); атомарные блокировки — только в общем кэше (Redis, БД).

## Файлы

- Диски `Storage` из `config/filesystems.php`: публичные файлы и приватные (доступ через контроллер с Policy или временные подписанные ссылки).
- Ограничения загрузки: размер, MIME по содержимому, количество; имя файла генерируется, а не берётся у пользователя.
- Обработка — в очереди; оригинал хранится до успешной обработки; удаление файлов — вместе с владельцем (жизненный цикл в статье фичи).

## Безопасность

- Авторизация каждого маршрута и действия: Policy или middleware; доступ к чужим данным по ID проверяется тестом.
- Массовое присвоение — только проверенные поля (Form Request `validated()`); `$fillable`/`$guarded` по принятому в проекте.
- Rate limiting: вход, восстановление пароля, отправка кодов, публичные API, дорогие операции.
- Чувствительные данные в БД — `encrypted` cast; персональные данные — сроки хранения и удаление по «Общим требованиям».
- Настройки — через `config()`, `env()` только в `config/*`.

## Изменения схемы без простоя

- Миграции обратимы и совместимы с кодом предыдущего релиза: сначала расширить (новая nullable-колонка, новая таблица), задеплоить код, заполнить данные, потом сужать (NOT NULL, удаление старого) — отдельным шагом или эпиком.
- Заполнение больших таблиц — джобом по чанкам, не в миграции.
- Индексы на больших таблицах и смена типов — с оценкой блокировок СУБД проекта.

## Время, деньги, локали

- Время хранится в UTC, показывается в часовом поясе пользователя или проекта; периоды и «конец дня» — с явным часовым поясом.
- Деньги — payments.md.

## Включение функций

- Рискованное или поэтапное включение — флагом функции (Laravel Pennant, если есть в проекте, или принятый способ); флаг удаляется после полного включения (задача в эпике).

## Тесты

- Авторизация: чужой пользователь получает 403/404.
- Валидация граничных значений; загрузка файла неверного типа и размера.
- Сброс кэша после изменения данных.
