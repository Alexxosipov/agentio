# Скилл внешней платформы

Агенты знают Laravel, но не знают правил каждой платформы: как приложение встраивается в Telegram или VK, как проверить, что данные пришли от платформы, а не от злоумышленника, какие лимиты и запреты. Ошибка здесь — уязвимость (поддельный пользователь) или приложение, которое платформа не пропустит. Поэтому первая задача по новой платформе — **скилл платформы**: его читают аналитик, архитектор, разработчики и ревьюер всех следующих задач.

Опирается на agentio-youtrack-workflow (процесс, вопросы к человеку) и agentio-develop-task (выполнение задачи, коммит, тесты). Вызовы API платформы — по правилу скилла agentio-saloon: есть поддерживаемый SDK — SDK, нет — Saloon; код — в `App\Integrations\<Платформа>`.

## Когда

- Архитектор планирует TASK «Скилл платформы <X>» первым шагом эпика, если продукт выходит на платформу или подключает сервис, а в `.claude/skills` нет скилла `<платформа>-development` (`ls .claude/skills`). Остальные задачи по платформе зависят от неё.
- Разработчик выполняет её по этому скиллу. Без такой задачи скиллы и документацию не создавай (guidelines Boost: документация — только по явному запросу); не хватает знаний о платформе в обычной задаче — `[AGENT:BLOCKED]` или `[AGENT:DECISION]` с предложением задачи на скилл.
- Скилл уже есть — дополняй его в задаче, которая находит пробел (новый раздел или reference), не создавай второй.

## Порядок

1. **Решение архитектора.** Прочитай задачу, эпик, «Архитектуру» статьи модуля или ADR: какая платформа, какие возможности нужны (авторизация, платежи, уведомления, вебхуки), SDK или Saloon, версия SDK, где код в проекте.
2. **Источники** (только проверяемые):
   - официальная документация платформы — `WebFetch` (разрешены домены официальной документации: core.telegram.org, docs.telegram-mini-apps.com, dev.vk.com, web.dev, developer.mozilla.org, docs.saloon.dev, laravel.com, github.com, raw.githubusercontent.com) и `WebSearch` для поиска страниц;
   - README, типы и исходники **установленных** SDK в `vendor/` и `node_modules/` — версия решает;
   - стартовые факты по платформам — [references/platforms.md](references/platforms.md): это отправная точка, а не источник истины — каждую деталь, которую пишешь в скилл, сверь с официальной документацией.
   - Нет доступа к источнику, а без него нельзя (алгоритм подписи, лимит) — не выдумывай: запиши «не проверено, источник: …» и вынеси в `[AGENT:BLOCKED]`, если от этого зависит безопасность.
3. **Скилл** — `.claude/skills/<платформа>-development/` (структура — [references/skill-template.md](references/skill-template.md)):
   - имя: строчные латинские буквы, цифры и дефисы, суффикс `-development` (`telegram-mini-app-development`, `vk-mini-app-development`, `pwa-development`); не `agentio-*` и не совпадает со скиллами Laravel Boost (`boost.json` → `skills`, `vendor/laravel/boost/.ai/**/skill/*`): `boost:update` перезаписывает каталог скилла с тем же именем;
   - `SKILL.md` до ~200 строк: frontmatter (`name` = имя каталога, `description` — что и когда применять: термины, файлы, маршруты платформы), правила и чек-лист; подробности — в `references/*.md` (по файлу на тему), ссылки на них из `SKILL.md`;
   - язык — русский, как остальные скиллы проекта; код и идентификаторы — как в платформе.
4. **Содержание — конкретно для этого проекта**: где лежит код платформы (по правилу раскладки ADR-001), какие маршруты, middleware, джобы, конфиг (`config/services.php`) и переменные `.env.example` её обслуживают — то, что уже есть или решено в «Архитектуре». Общие пересказы документации без связи с проектом не нужны.
5. **Безопасность — обязательный раздел**: как сервер проверяет подлинность данных платформы (подписи, секреты вебхуков, срок жизни данных), что нельзя доверять данным с клиента, где хранятся секреты. С примером кода проверки на PHP и тестом с правильной и поддельной подписью.
6. **Тестирование — обязательный раздел**: как подделать входящие данные платформы в тестах (фабрика подписанных данных), фейки HTTP (Saloon `MockClient`), что проверять вручную и как (тестовая среда платформы, туннель к локальному серверу).
7. **Проверка**: файлы скилла проходят `composer test` (форматтеры не трогают Markdown, но код примеров должен быть корректным PHP/JS); если задача включает код (например, middleware проверки подписи) — он с тестами по agentio-develop-task.
8. **Итог**: `[AGENT:DONE]` со списком разделов скилла и непроверенных мест; в описание эпика — строка «Скилл платформы: `.claude/skills/<имя>`» (через PM/оркестратора, если описание эпика ведёт он).

## Чек-лист

- [ ] Имя `<платформа>-development`, не конфликтует с agentio-* и Boost; frontmatter `name`/`description`.
- [ ] Факты сверены с официальной документацией и установленными SDK; непроверенное помечено.
- [ ] Разделы: обзор и встраивание, код в проекте, безопасность с примером и тестом, ограничения и лимиты, тестирование, ссылки на документацию с версией.
- [ ] Интеграция по HTTP без SDK — по agentio-saloon; новые SDK не установлены без решения человека.
- [ ] Ничего не выдумано: нет источника — пометка и вопрос.
