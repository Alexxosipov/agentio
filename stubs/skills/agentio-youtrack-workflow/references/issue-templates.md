# Шаблоны описаний задач

## Содержание

- [EPIC] · [STORY] · [TASK] · [IDEA]

Описание передаётся в `description` инструментов `mcp__youtrack__create_issue` / `update_issue`. Ссылки на статьи — по ID (`{{kb.architecture.overview}}`), на правило или требование статьи фичи — ID статьи и номер (`{{project}}-A-31 BR-2`), на задачи — по ID (`{{project}}-34`). Описание должно быть самодостаточным: исполнитель не видит переписку, только YouTrack и репозиторий.

## [EPIC]

```markdown
## Ценность
Кто получает, что именно, почему сейчас. 1–3 предложения.

## Источник
Идея: {{project}}-1.

## Границы
**Входит:** ...
**Не входит:** ...

## Критерии успеха
- Измеримые / проверяемые утверждения.

## Аналитика и архитектура
- Сводка влияния: см. комментарий `[AGENT:DECISION]` системной аналитики (скилл agentio-system-analyst).
- Статьи фич и решения: {{project}}-A-… (<Модуль> → <Фича>: FR-.., BR-.., AD-1…AD-3), …
- Статьи модулей: {{project}}-A-… («Архитектура модуля»: AD-..); ADR: {{project}}-A-…

## Порядок реализации
| # | Шаг | Фича / решение | Зависит от | Затрагивает файлы |
|---|---|---|---|---|
| 1 | … | {{project}}-A-… AD-1 | — | … |

**Параллельные группы:** …; **нельзя параллельно:** …
(Пишет скилл agentio-laravel-architect; STORY и TASK создаёт PM по этому порядку.)

## Ветка
`<ID эпика>` от `{{base_branch}}` (создаётся автоматически циклом агентов, `php artisan agentio:run`)
```

## [STORY]

```markdown
## Сценарий
Как <роль>, я хочу <действие>, чтобы <ценность>.

## Критерии приёмки
1. **Given** ... **When** ... **Then** ...
2. **Given** ... **When** ... **Then** ...
(негативные сценарии и права доступа — отдельными критериями)

## Контекст
Статья фичи: {{project}}-A-… (сценарий, FR/BR); ADR: {{project}}-A-…

## Задачи
Создаются как подзадачи, порядок — через `depends on`.
```

## [TASK]

```markdown
## Контекст
Зачем эта задача в рамках STORY {{project}}-.. (1–2 предложения). Статьи: {{project}}-A-… (фича: FR-.., BR-.., решения AD-..), {{project}}-A-… (модуль, если нужен).

## Что сделать
Одно атомарное изменение. Конкретно: классы (полные имена в неймспейсе домена — `App\<Домен>\<Вид>\<Класс>`), маршруты, компоненты, миграции, тесты (пути зеркалят неймспейс класса).

## Критерии приёмки
- [ ] Проверяемый результат 1 (желательно в виде теста: «feature-тест X проверяет Y»).
- [ ] Тесты добавлены, `php artisan agentio:test` проходит (и требования проекта к покрытию, если они есть).

## Затрагиваемые области кода (оценка)
- `app/<Домен>/Actions/...` (новый)
- `tests/Unit/<Домен>/Actions/...Test.php` (новый, зеркалит неймспейс класса)
- `database/migrations/...` (новая миграция — конфликтует с другими миграциями этой волны)
- `resources/...` (представления или фронтенд)

## Вне рамок
Что НЕ делать в этой задаче (чтобы исполнитель не расползался).
```

## [IDEA]

Заводит человек, свободной формой. Достаточно: что хочется, для кого, почему. Метка `idea` или `Type: Idea`, `Stage: Backlog` (значение по умолчанию для новых задач).
